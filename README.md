# Сайт SMM-агентства «Как есть»

Одностраничный лендинг: чистый HTML + CSS + JS, без сборки и зависимостей.
Открывается двойным кликом по `index.html` или отдаётся любым статическим хостингом
(Netlify, Vercel, GitHub Pages, обычный nginx).

## Локальный просмотр

```bash
python3 -m http.server 4173
```

Затем открыть http://localhost:4173

## Блог

`blog/index.html` — список статей с фильтром по рубрикам, плюс 20 отдельных страниц.
Ссылки на блог стоят в меню шапки и в подвале главной.

Контент лежит отдельно от вёрстки:

- `blog/_articles.py` — все тексты: заголовок, описание, рубрика, дата, анонс, тело статьи;
- `blog/_generate.py` — сборка страниц, списка и `sitemap.xml`.

Добавить статью: дописать словарь в `ARTICLES` и выполнить из корня проекта

```bash
python3 blog/_generate.py
```

Пересоберутся все страницы, список и карта сайта. Время чтения считается автоматически,
блок «Читайте также» подбирается по рубрике.

### Обложки статей

Лежат в `blog/covers/` с именем по слагу статьи: `covers/<slug>.jpg`. Генератор
подхватывает их сам — картинка появляется в карточке, на странице статьи и в `og:image`.
Файла нет — страница собирается без обложки, вёрстка не ломается.

Все двадцать сгенерированы через Nano Banana (`gemini-2.5-flash-image`).
Промпты и общий блок стиля — в `blog/covers/PROMPTS.md`:

```bash
export GEMINI_API_KEY="ключ"
python3 blog/_covers.py generate   # сгенерировать недостающие
python3 blog/_covers.py check      # каких обложек не хватает
python3 blog/_covers.py fit        # привести файлы к 1200x630 JPEG
```

Скрипт генерирует только недостающие: чтобы переделать одну обложку, удалите её файл
и запустите `generate` снова. Модель отдаёт 16:9, `fit` обрезает под 1200×630 —
без обрезки картинку растянуло бы.

В блоке стиля стоит жёсткий запрет на любой текст, включая коды цветов: модель
охотно рисует надписи вроде «2563EB» или «SUSCRIBE», если промпт даёт повод.

Иллюстрации для страниц услуг лежат в `assets/img/uslugi/` и делаются тем же способом:

```bash
python3 pages/_heroes.py
```

Что уже сделано для поиска: уникальные `title` и `description`, канонические адреса,
Open Graph, микроразметка Article и Blog, хлебные крошки, `sitemap.xml` и `robots.txt`
с доменом `kakestsmm.ru`. Если домен другой — поменяйте константу `SITE`
в `blog/_generate.py` и пересоберите.

### Отзывы

`otzyvy.html` — шесть реальных отзывов, тексты в `REVIEWS` в `pages/_content.py`.
Разметка `Review` с `AggregateRating` (5 из 5, 6 отзывов) строится из тех же данных.

Важно: Google не показывает звёзды в выдаче для отзывов, размещённых бизнесом на своём
же сайте, — это правило про self-serving reviews. Разметка всё равно полезна: её
учитывает Яндекс, и она передаёт поисковикам структуру страницы.

## SEO

Что настроено на всех 27 страницах: уникальные `title` и `description`, `canonical`,
`robots` с `max-image-preview:large`, полный набор Open Graph и Twitter Card,
`theme-color` и `apple-touch-icon`.

Микроразметка на главной: `Organization` (контакты и профили в соцсетях через `sameAs`),
`WebSite`, `Service` с каталогом услуг и `FAQPage` — последняя даёт расширенный сниппет
с вопросами прямо в выдаче. В блоге — `Article` на статьях и `Blog` на списке.

Карточки для соцсетей лежат в `assets/og/`, собираются командой

```bash
python3 assets/og/_draw.py
```

Тексты карточек правятся в списке `CARDS` в том же файле. У статей блога роль карточки
играет обложка статьи, у остальных страниц — `og-main`, `og-blog` и `og-legal`.

Блок «Частые вопросы» на главной и разметка `FAQPage` собраны из одного текста:
при правке вопросов в `index.html` нужно перегенерировать разметку, иначе она разойдётся
с видимым текстом — это нарушение правил поисковиков.

### Подтверждение прав в поисковиках

Яндекс.Вебмастер подтверждён двумя способами сразу — если один не сработает, останется второй:

| Поисковик | Файл в корне | Мета-тег в `index.html` |
|---|---|---|
| Яндекс | `yandex_e64169ea3faae403.html` | `yandex-verification` |
| Bing | `BingSiteAuth.xml` | `msvalidate.01` |
| Google | — | пока не подключён |

Содержимое файлов подтверждения менять нельзя. Для Google нужен код из Search Console,
добавляется таким же мета-тегом.

Даты в `sitemap.xml` берутся из времени последней правки файла, а не из даты сборки:
иначе поисковику сообщалось бы, что весь сайт изменился при пересборке одной страницы.

### Региональность

Регион сайта — вся Россия, карточки в Яндекс Бизнесе нет. Поэтому в микроразметке
указан только `areaServed: Россия`, без города: машиночитаемый `PostalAddress`
с Саяногорском тянул бы региональность к Хакасии. Адрес остаётся видимым текстом
в реквизитах на странице контактов и в юридических документах — там он обязателен.

## Попап с заявкой

Всплывает через 10 секунд, показывается один раз: если заявку оставили — больше никогда,
если закрыли — через 7 дней. Если посетитель сам доскроллил до контактов раньше
10 секунд, попап не появляется.

Заявки уходят в Telegram-бот **@kakestsmmbot** через промежуточный обработчик.
Токен бота в код страницы не попадает — почему именно так и как развернуть,
описано в [deploy/README.md](deploy/README.md).

**Пока не задана константа `LEAD_ENDPOINT` в [assets/js/main.js](assets/js/main.js),
форма показывает экран «Не удалось отправить»** с кнопкой написать напрямую.
Это сделано намеренно: раньше форма показывала «Заявка принята» всегда, и при любом
сбое заявка терялась молча.

Настройки в том же файле: `DELAY` — задержка показа, `SNOOZE_DAYS` — на сколько
прятать после закрытия.

## Настройка

Цвета и размеры — в `:root` в начале `assets/css/style.css`:
`--blue` — фирменный синий, `--container` — ширина контентной области,
`--r`, `--r-lg` — скругления, `--tint` — серый фон секций.

Порядок и состав логотипов в бегущей строке — блок `#clients` в `index.html`
(JS дублирует список, чтобы прокрутка была бесшовной).
